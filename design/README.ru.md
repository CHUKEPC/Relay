# design/ — сюда кладите результат из Claude Design

*[English version](README.md)*

Эта папка — **эталон внешнего вида и ощущений от интерфейса**. Сборка читает всё, что здесь лежит, и
согласует это с функциональной спецификацией в [`../docs/FEATURES.ru.md`](../docs/FEATURES.ru.md).

## Лучший формат для импорта (в порядке приоритета)

Приложение написано на **React + TypeScript + Tailwind CSS**, поэтому напрямую пригоднее всего такие экспорты:

1. **Компоненты React + Tailwind** — файлы `.tsx` / `.jsx`. **Наилучший возможный вход.** Сборка
   адаптирует их в `src/renderer/components` и `src/renderer/features` с минимальными изменениями.
2. **Дизайн-токены** — цвета, типографика, отступы, скругления, тени в виде **CSS-переменных**
   (`globals.css` с `:root` / `.dark`) и/или `theme.ts`/`tokens.json`. Они определяют
   `tailwind.config.ts` и светлую/тёмную темы. Если они у вас есть, всегда прикладывайте их.
3. **Статические макеты на HTML + CSS** — пригодны как образец структуры/стилей; сборка перенесёт
   их на React.
4. **Скриншоты / изображения** — `.png` / `.svg` целых экранов. Наименьшая точность (кода нет), но
   очень полезны как визуальный ориентир для раскладки и отступов. Прикладывайте их, даже если у вас есть и код.

> Если вы пользовались инструментами Claude для артефактов/дизайна, выбирайте экспорт **React with Tailwind**, когда его предлагают.
> Это самый чистый путь. Экспортируйте **экраны целиком** (конструктор запросов, боковую панель/коллекции,
> просмотр ответа, окружения, историю, настройки и панель AI-ассистента), а не только отдельные
> виджеты, чтобы сборка понимала раскладку полностью.

## Что куда класть

```
design/
├── components/   # exported .tsx/.jsx components (buttons, inputs, tabs, panels, modals, ...)
├── screens/      # full-screen layouts as .tsx OR mockup images (.png/.svg) for reference
├── tokens/       # globals.css (CSS variables), theme.ts / tokens.json, tailwind snippets
├── assets/       # icons (.svg), logo, custom fonts, illustrations
└── (this README)
```

Подойдёт что угодно: если у вас только скриншоты, положите их в `screens/`. Если только файл
токенов — в `tokens/`. Сборка написана так, чтобы использовать всё, что есть, а для всего недостающего
откатываться на аккуратную дизайн-систему по умолчанию.

## Какие экраны желательно охватить в дизайне

- Оболочка приложения: верхняя панель, левая боковая панель (коллекции), область запросов с вкладками, область ответа снизу/сбоку.
- Конструктор запросов: выбор метода + адресная строка + Send; вкладки Params, Headers, Body, Auth,
  Pre-request/Tests, Settings.
- Просмотр ответа: статус/время/размер, вкладки Body (pretty/raw/preview), Headers, Cookies, Tests.
- Боковая панель коллекций и окружений; менеджер окружений/переменных; список истории.
- **Панель AI-ассистента** (комплект возможностей): лента чата, выбор провайдера/модели, поле ввода
  и действия над сообщениями (например, «применить к запросу»).
- Настройки: провайдеры и API-ключи, тема, параметры запросов по умолчанию.

## Примечания

- Используйте **CSS-переменные** для всех цветов, чтобы светлая/тёмная темы работали автоматически.
- Если у вас есть логотип/иконка приложения, положите квадратный PNG (≥512px) и/или SVG в `assets/`; они будут
  использованы для окна и иконки собранного приложения.
