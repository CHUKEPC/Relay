# Relay с нуля: скачать, собрать, запустить и проверить

*[English version](README.md)*

Эта инструкция — для тех, кто никогда не собирал программы из исходного кода. Ничего знать
заранее не нужно: каждый шаг расписан, а всю техническую работу делают готовые скрипты из этой
папки — их достаточно запускать по порядку двойным щелчком.

**Relay** — настольная программа для тестирования API: она отправляет запросы веб-сервисам и
показывает их ответы. В этой папке, кроме скриптов, лежит демонстрационный «интернет-магазин»
и готовые примеры запросов к нему — на них можно сразу проверить, что всё работает.

| Что понадобится | |
|---|---|
| Компьютер | Windows 10 или 11, macOS 11 или новее, Linux (Ubuntu 22.04+, Debian 12+, Fedora 38+ и похожие) |
| Интернет | около 750 МБ скачивается один раз |
| Место на диске | около 2 ГБ |
| Время | 15–30 минут, большая часть — ожидание загрузки |

## Не хотите собирать? Скачайте готовую программу

Готовые установщики последней версии лежат на [Google Диске][gdrive]. Возьмите файл для своей
системы:

| Система | Файл | Как установить |
|---|---|---|
| Windows (обычный ПК) | `Relay-<версия>-Setup.exe` | Запустите файл и следуйте шагам установщика |
| Windows на процессоре ARM | `Relay-<версия>-arm64-Setup.exe` | То же самое |
| Linux (обычный ПК) | `relay-api-client-<версия>.tar.gz` | Распакуйте и запустите — см. [шаг 7](#первый-запуск-неподписанной-программы) |
| Linux на процессоре ARM | `relay-api-client-<версия>-arm64.tar.gz` | То же самое |
| macOS | `Relay-<версия>-arm64.dmg` (Apple M1–M4), `Relay-<версия>-x64.dmg` (Intel) | Откройте, перетащите Relay в «Программы». Если файлов для macOS на диске нет, соберите их на Mac по [шагу 7](#шаг-7-собрать-установщик-по-желанию) |

Программа не подписана платным сертификатом разработчика, поэтому при первом запуске система
предупредит о неизвестном издателе — что нажать, написано в
[шаге 7](#первый-запуск-неподписанной-программы).

Чтобы потом проверить программу на примерах (шаг 5), всё равно понадобятся Node.js (шаг 1) и папка
с примерами (шаг 2): демонстрационный сервис запускается через Node.js.

## Несколько слов, которые встретятся дальше

| Слово | Что это |
|---|---|
| **GitHub** | Сайт, где хранится исходный код программ. Код Relay лежит на github.com/CHUKEPC/Relay |
| **Исходный код** | Текст программы, из которого собирается то, что запускается. Его можно скачать одним архивом |
| **Node.js** | Бесплатная программа, которая нужна, чтобы собрать и запустить Relay из исходного кода |
| **npm** | Устанавливается вместе с Node.js и скачивает компоненты, из которых состоит Relay |
| **Терминал** | Окно, в котором набирают команды. Скрипты из этой папки открывают его сами |
| **Сборка** | Превращение исходного кода в работающую программу. Скрипты делают её автоматически |
| **Установщик** | Один файл (`.exe`, `.dmg`, `.AppImage`), который ставит программу на любой компьютер |
| **API, запрос, ответ** | Программы общаются по сети: одна отправляет запрос, другая присылает ответ. Relay показывает и то, и другое |
| **Сервер, порт, 127.0.0.1** | Сервер — программа, которая отвечает на запросы. `127.0.0.1` — адрес «этого же компьютера», порт — номер «двери», у демо-сервиса это 8470 и 8471 |

### Как открыть терминал

Скриптам из этой папки терминал не нужен — они открывают окно сами. Но он пригодится, чтобы проверить
версию Node.js или выполнить команду из раздела «Если что-то пошло не так».

- **Windows:** нажмите `Win + R`, введите `cmd` и нажмите Enter. Или: «Пуск» → начните печатать
  «Терминал» → откройте его.
- **macOS:** нажмите `Cmd + Пробел`, введите «Терминал» и нажмите Enter.
- **Linux:** нажмите `Ctrl + Alt + T` или найдите «Терминал» в меню приложений.

## Шаг 1. Установить Node.js

Нужна версия **20 или новее**. На сайте её отмечают как **LTS** — это «долгосрочная поддержка»,
самая стабильная версия.

**Windows**

1. Откройте https://nodejs.org и нажмите большую кнопку с надписью **LTS**.
2. Запустите скачанный файл `node-v…-x64.msi` и нажимайте «Next», пока не появится «Finish».
   Галочку «Automatically install the necessary tools» ставить не нужно.

Если Node.js забыли поставить, первый же скрипт из шага 3 скажет об этом и предложит установить его
сам (через встроенный в Windows установщик winget) или откроет сайт.

**macOS**

1. Откройте https://nodejs.org, нажмите **LTS** и скачайте **macOS Installer (.pkg)**.
2. Откройте файл `.pkg` и пройдите установку («Продолжить» → «Установить», понадобится пароль от
   компьютера).

**Linux**

Пакеты из стандартного магазина приложений часто слишком старые, поэтому поставьте Node.js через
nvm — так рекомендует сам nodejs.org. Откройте терминал и выполните по очереди:

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
```

Закройте терминал, откройте новый и выполните:

```bash
nvm install --lts
```

Если `curl` не найден, сначала выполните `sudo apt install curl` (Ubuntu, Debian) или
`sudo dnf install curl` (Fedora).

**Проверка.** Откройте **новый** терминал и выполните:

```bash
node -v
```

Должно появиться что-то вроде `v22.11.0`. Первое число — 20 или больше? Значит, всё в порядке.

## Шаг 2. Скачать Relay с GitHub

### Вариант А — архивом (проще всего)

1. Откройте https://github.com/CHUKEPC/Relay.
2. Нажмите зелёную кнопку **«Code»** и в открывшемся меню — **«Download ZIP»**.
3. Распакуйте архив:
   - **Windows:** правый щелчок по `Relay-main.zip` → «Извлечь все…» → «Извлечь»;
   - **macOS:** двойной щелчок по архиву;
   - **Linux:** правый щелчок → «Извлечь сюда» (или в терминале `unzip Relay-main.zip`).

Появится папка `Relay-main`. Лучше положить её туда, где в пути нет русских букв и пробелов,
например `C:\Relay-main` в Windows или в папку «Документы» в macOS и Linux.

### Вариант Б — через Git (удобно обновлять)

Git — программа, которая скачивает код с GitHub и потом подтягивает обновления одной командой.

- **Windows:** скачайте установщик с https://git-scm.com и нажимайте «Next» до конца.
- **macOS:** в терминале выполните `git --version` — если Git не установлен, macOS сама предложит
  поставить «инструменты командной строки», согласитесь.
- **Linux:** `sudo apt install git` (Ubuntu, Debian) или `sudo dnf install git` (Fedora).

Затем в терминале перейдите в папку, куда хотите положить Relay, и выполните:

```bash
git clone https://github.com/CHUKEPC/Relay.git
```

Появится папка `Relay`.

> Дальше папку проекта (`Relay-main` или `Relay`) мы будем называть просто **папкой Relay**.
> Эта инструкция и скрипты лежат внутри неё, в папке `getting-started`.

## Шаг 3. Установить компоненты

Откройте папку Relay → `getting-started` → папку своей системы: `windows`, `macos` или `linux`.
Скрипты в ней пронумерованы — запускайте их по порядку.

**Windows.** Дважды щёлкните `1-install.cmd`. Если Windows спросит «Не удаётся проверить издателя…»
или покажет синее окно «Система Windows защитила ваш компьютер», нажмите «Запустить» (или
«Подробнее» → «Выполнить в любом случае»): скрипт скачан из интернета, и Windows так предупреждает
о любом таком файле.

**macOS.** В первый раз щёлкните `1-install.command` **правой кнопкой** → «Открыть» → «Открыть».
Обычный двойной щелчок macOS заблокирует, потому что файл скачан из интернета; после первого
раза заработает и он. Остальные скрипты в первый раз открывайте так же.

**Linux.** Откройте терминал в папке Relay (правый щелчок по пустому месту в папке →
«Открыть в терминале») и выполните:

```bash
bash getting-started/linux/1-install.sh
```

Откроется окно с текстом. Скрипт проверит Node.js и скачает компоненты — около 750 МБ, обычно
2–10 минут. Строки со словом `WARN` во время загрузки — это нормально. Дождитесь сообщения:

```
✔ Готово! Компоненты установлены.
```

Если вместо этого появилось сообщение об ошибке, загляните в раздел
[«Если что-то пошло не так»](#если-что-то-пошло-не-так). Скрипт сам предложит повторить загрузку
через запасной сервер, если основной недоступен.

## Шаг 4. Запустить Relay

Запустите `2-start-relay` (Windows: `2-start-relay.cmd`, macOS: `2-start-relay.command`,
Linux: `bash getting-started/linux/2-start-relay.sh`).

В первый раз скрипт соберёт программу (1–2 минуты), потом откроет её окно. Следующие запуски
занимают несколько секунд: пересборка происходит, только если исходный код изменился. Когда появится
`✔ Relay запущен в отдельном окне.`, окно со скриптом можно закрыть — Relay продолжит работать.

**Первое знакомство.** При первом запуске Relay предложит короткий тур по интерфейсу — пройдите его
или нажмите «Пропустить».

**Язык.** Relay открывается на русском. Английский выбирается в «Настройки» (внизу боковой панели,
или `Ctrl + ,`, в macOS `Cmd + ,`) → «Основные» → «Язык интерфейса».

## Шаг 5. Проверить на примерах

Примеры обращаются к демонстрационному «интернет-магазину», который работает прямо на вашем
компьютере: в интернет ничего не уходит, а ответы всегда одинаковые.

### 5.1. Запустите демо-сервис

Запустите `3-demo-server`. Откроются два окна:

- **папка с примерами** `getting-started/demo` — она понадобится в следующем пункте;
- **окно сервиса** — в нём видно каждый пришедший запрос. **Не закрывайте его**, пока проверяете
  примеры: закроете — сервис остановится.

Сервис поднимает два «стенда» — как будто это два разных сервера:

| Стенд | Адрес |
|---|---|
| Локальный стенд | http://127.0.0.1:8470 |
| Тестовый стенд | http://127.0.0.1:8471 |

### 5.2. Загрузите примеры в Relay

В папке с примерами выделите четыре файла (щёлкайте по ним с зажатой клавишей `Ctrl`,
в macOS — `Cmd`):

- `shop-api.postman_collection.json` — коллекция «Интернет-магазин API»: 7 запросов, 13 проверок;
- `payment-gateway.postman_collection.json` — «Платёжный шлюз (песочница)»: 2 запроса с OAuth 2.0;
- `local-stand.postman_environment.json` и `test-stand.postman_environment.json` — окружения
  «Локальный стенд» и «Тестовый стенд».

Перетащите их мышью в окно Relay. Слева, в разделе «Коллекции», появятся обе коллекции.

**Выберите окружение.** Вверху окна Relay, справа от поиска, нажмите «Без окружения» и выберите
**«Локальный стенд»**. Окружение — это набор переменных: например, `{{baseUrl}}` в адресах запросов
превратится в `http://127.0.0.1:8470`.

### 5.3. Проверьте по шагам

Запрос открывается щелчком по нему в боковой панели, отправляется кнопкой **«Отправить»**
(или `Ctrl + Enter`, в macOS `Cmd + Enter`). Ответ появляется в нижней части окна.

1. **Проверка доступности.** Откройте «Интернет-магазин API» → «Проверка доступности» → «Отправить».
   Ответ: `200 OK` и название стенда. Переключите окружение на «Тестовый стенд», отправьте ещё
   раз — ответит второй стенд. Верните «Локальный стенд».

2. **Вход с паролем.** «Авторизация» → «Вход по паролю» → «Отправить». Откройте вкладку **Tests**
   в ответе: 3 проверки пройдены. Сценарий на вкладке Scripts → Post-response сохранил полученный
   токен в переменную `token` — остальные запросы коллекции подставляют его сами.

   ![Вход по паролю: ответ 200, три пройденные проверки](images/login-tests.png)

3. **Каталог.** «Каталог» → «Список товаров» → «Отправить»: список из 5 товаров. Наведите курсор
   на `{{baseUrl}}` в адресе — Relay покажет значение переменной и откуда оно взято.

4. **Цепочка заказов.** «Заказы» → «Создание заказа» → `201 Created`, номер заказа запоминается в
   переменной `orderId`. Затем «Получение заказа» (`200`) и «Отмена заказа» (`204`) — они работают
   с тем самым заказом.

5. **Раннер — все запросы разом.** Правый щелчок по коллекции «Интернет-магазин API» → «Запустить» →
   «Запустить». Ожидаемый результат: **запросов 7, тестов пройдено 13, провалено 0**. Кнопка
   «Отчёт» сохраняет результат в файл.

   ![Раннер: 7 запросов, 13 пройденных тестов](images/runner.png)

6. **Файл данных.** Правый щелчок по папке «Каталог» → «Запустить» → «Выбрать файл» →
   `catalog-data.csv` из папки с примерами → «Запустить»: 5 повторов, по одному на товар
   101–105, все проверки проходят. С файлом `catalog-data-negative.csv` повтор с несуществующим
   товаром 999 получит ответ `404`, и раннер покажет, какие проверки провалились, — так и задумано.

7. **OAuth 2.0.** «Платёжный шлюз (песочница)» → «Создание платежа» → вкладка **Authorization** →
   «Получить токен» → «Отправить»: `201`. Затем «Статус платежа»: «Получить токен» → «Отправить» →
   `200`, 2 проверки пройдены.

   ![OAuth 2.0: статус платежа, 200 OK](images/oauth.png)

8. **Настоящий интернет.** Создайте новую вкладку (`Ctrl + N`, в macOS `Cmd + N`), вставьте в
   адресную строку `https://httpbin.org/get` и нажмите «Отправить». Ответ `200` с данными о
   запросе означает, что Relay ходит и во внешнюю сеть.

### 5.4. Ещё несколько возможностей

- **Группы вкладок.** Правый щелчок по папке «Заказы» → «Открыть запросы группой вкладок».
  Щелчок по цветному ярлыку сворачивает и разворачивает группу, правый щелчок — название, цвет и
  действия. Перетащите вкладку на ярлык или на вкладки группы — она войдёт в группу; бросьте её в
  промежуток между группами — не войдёт ни в одну.
- **Корзина.** Удалите любой запрос (правый щелчок → «Удалить») и нажмите «Восстановить» во
  всплывающем сообщении или откройте «Корзина» внизу боковой панели. Сколько дней хранить удалённое,
  выбирается в «Настройки» → «Данные».
- **Подсказки переменных.** В теле запроса «Создание заказа» наберите `{{` — появится список
  переменных, а `{{$` — динамические переменные вроде `{{$guid}}` и `{{$randomInt}}`.
- **Beautify.** Вставьте в тело `{"productId":{{productId}},"quantity":1}` и нажмите «Beautify» —
  JSON выровняется, даже если переменные стоят без кавычек.
- **Код запроса.** Кнопка «Код» показывает тот же запрос на cURL и ещё на десятке языков.

### Логины и пароли демо-сервиса

| Что | Значение |
|---|---|
| Логин и пароль магазина | `tester` / `secret` |
| Клиент OAuth 2.0 (платёжный шлюз) | `relay-desktop` / `demo-secret` |

Все они уже вписаны в окружения, вводить их вручную не нужно. Данные сервиса живут в памяти:
после его перезапуска заказы снова нумеруются с 5001 (локальный стенд) и 7001 (тестовый).

## Шаг 6. Автоматические тесты (по желанию)

Запустите `4-run-tests`. Около минуты программа проверяет сама себя — почти тысячу тестов. В конце
появится сводка примерно такого вида (числа могут немного отличаться):

```
 Test Files  79 passed (79)
      Tests  968 passed | 9 skipped (977)
✔ Все тесты пройдены.
```

`passed` — тест пройден. `skipped` — тесты, которые ходят на внешние сайты; они выключены, чтобы
результат не зависел от интернета. Слова `failed` в сводке быть не должно.

## Шаг 7. Собрать установщик (по желанию)

Установщик — это один файл, который можно перенести на другой компьютер и установить Relay как
обычную программу, без Node.js и без этой папки. Запустите `5-build-installer` и подождите 2–5 минут.
Готовый файл появится в папке `release` внутри папки Relay, скрипт покажет его путь:

| Система | Файл в `release` |
|---|---|
| Windows | `Relay-<версия>-Setup.exe` |
| macOS | `Relay-<версия>-arm64.dmg` (Apple M1–M4) или `Relay-<версия>-x64.dmg` (Intel) |
| Linux | `Relay-<версия>.AppImage` |

Установщик собирается для той системы, на которой запущен скрипт: файл для macOS делается на Mac,
для Linux — в Linux.

### Первый запуск неподписанной программы

У Relay нет платного сертификата разработчика, поэтому системы предупреждают о неизвестном издателе.

- **Windows:** в окне «Система Windows защитила ваш компьютер» нажмите «Подробнее» →
  «Выполнить в любом случае».
- **macOS:** откройте `.dmg`, перетащите Relay в «Программы». В первый раз запустите его правым
  щелчком → «Открыть» → «Открыть». Если macOS пишет, что программа «повреждена» или «не может быть
  открыта», откройте «Системные настройки» → «Конфиденциальность и безопасность» и нажмите «Всё равно
  открыть» внизу страницы.
- **Linux (AppImage):** файл нужно сделать запускаемым — правый щелчок → «Свойства» → «Права» →
  «Разрешить выполнение», или в терминале:

  ```bash
  chmod +x Relay-*.AppImage
  ./Relay-*.AppImage
  ```

  Если AppImage не запускается и пишет про `libfuse`, установите `sudo apt install libfuse2`
  (в Ubuntu 24.04 — `sudo apt install libfuse2t64`). Пакет `.deb` ставится командой
  `sudo apt install ./relay_<версия>_amd64.deb`.
- **Linux (архив `tar.gz`):** распакуйте и запустите в терминале:

  ```bash
  tar -xzf relay-api-client-*.tar.gz
  cd relay-api-client-*/
  ./relay-api-client
  ```

  Если программа не запускается и пишет про `chrome-sandbox` или `sandbox`, запустите её с ключом
  `./relay-api-client --no-sandbox`.

## Если что-то пошло не так

Сначала запустите диагностику — она покажет, что установлено и чего не хватает. В терминале,
в папке Relay:

```bash
node getting-started/scripts/helper.mjs doctor
```

| Что видно | Что делать |
|---|---|
| `"node" не является внутренней или внешней командой` / `node: command not found` | Node.js не установлен, или терминал открыт до установки. Выполните шаг 1 и откройте новое окно |
| `Установлен Node.js 18…, а нужен 20 или новее` | Установлена старая версия. Поставьте LTS с nodejs.org (шаг 1) |
| Скрипт в macOS не открывается двойным щелчком | Правый щелчок → «Открыть» → «Открыть». Если пишет «нет прав», в терминале в папке Relay: `chmod +x getting-started/macos/*.command` |
| `Скачать компоненты не удалось`, `ETIMEDOUT`, `ECONNRESET` | Нет интернета или мешает прокси, VPN или антивирус. Согласитесь на повтор через запасной сервер или запустите `1-install` ещё раз |
| `EPERM`, `operation not permitted` (Windows) | Файлы держит антивирус или открытый Relay. Закройте Relay и запустите `1-install` ещё раз |
| В Linux окно Relay не открывается, в журнале `error while loading shared libraries` | Не хватает системных библиотек: `sudo apt install libgtk-3-0 libnss3 libgbm1 libasound2` (в Ubuntu 24.04 вместо `libasound2` — `libasound2t64`) |
| Запросы отвечают `ECONNREFUSED` | Демо-сервис не запущен или его окно закрыто. Запустите `3-demo-server` снова |
| `Не удалось запустить «Локальный стенд» на порту 8470` | Порт занят другой программой (если сервис уже запущен, скрипт скажет об этом сам и второй раз его не запустит): запустите сервис на других портах (`node getting-started/demo/demo-server.mjs 9470 9471`) и поменяйте `baseUrl` в окружениях |
| `401 unauthorized` | Сначала отправьте «Вход по паролю» и проверьте, что вверху выбрано окружение «Локальный стенд» |
| `release\win-unpacked занята` при сборке установщика | Закройте Relay, запущенный из этой папки, и повторите `5-build-installer` |

Журнал последнего запуска Relay скрипт `2-start-relay` пишет во временную папку системы, в файл
`relay-start.log`, и показывает его путь, если что-то пошло не так.

## Как обновить и как удалить

**Обновить.** Скачайте архив заново (вариант А) или выполните в папке Relay `git pull` (вариант Б).
Затем запустите `1-install` (если компоненты изменились, он их докачает) и `2-start-relay` — сборка
обновится сама.

**Удалить.** Удалите папку Relay. Данные программы — коллекции, окружения, история — хранятся
отдельно, в папке пользователя:

| Система | Папка с данными |
|---|---|
| Windows | `%APPDATA%\Relay` |
| macOS | `~/Library/Application Support/Relay` |
| Linux | `~/.config/Relay` |

Её тоже можно удалить, если данные больше не нужны. Relay, собранный из исходного кода, и Relay из
установщика пользуются одной и той же папкой с данными.

## Для тех, кто знаком с терминалом

Скрипты — это обёртки над обычными командами, которые выполняются в папке Relay:

```bash
npm ci                                # компоненты (то же, что 1-install)
npx electron-vite build               # сборка в папку out/
npx electron .                        # запуск собранной программы
npm run dev                           # режим разработки с горячей перезагрузкой
node getting-started/demo/demo-server.mjs   # демо-сервис
npm test                              # автоматические тесты (Vitest)
npm run build:win                     # установщик Windows; также build:mac и build:linux
```

## Что лежит в этой папке

| Путь | Назначение |
|---|---|
| `windows/1-install.cmd` … `5-build-installer.cmd` | Скрипты для Windows: запуск двойным щелчком |
| `macos/1-install.command` … `5-build-installer.command` | То же для macOS |
| `linux/1-install.sh` … `5-build-installer.sh` | То же для Linux: `bash getting-started/linux/<скрипт>` |
| `scripts/helper.mjs` | Общая логика всех скриптов: установка, сборка, запуск, тесты, диагностика |
| `scripts/check-node.cmd`, `scripts/check-node.sh` | Проверяют, что Node.js установлен, и подсказывают, как его поставить |
| `demo/demo-server.mjs` | Демонстрационный «интернет-магазин» (нужен только Node.js) |
| `demo/*.postman_collection.json` | Коллекции запросов: «Интернет-магазин API», «Платёжный шлюз (песочница)» |
| `demo/*.postman_environment.json` | Окружения «Локальный стенд» и «Тестовый стенд» |

| `images/` | Картинки к этой инструкции |

Сообщения скриптов выводятся на языке системы — русском или английском. Сменить язык можно
переменной окружения `RELAY_LANG=en` или `RELAY_LANG=ru`.
