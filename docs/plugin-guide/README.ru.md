## 1. Два вида плагинов

Любой плагин — это папка с файлом `plugin.json`. Что ещё лежит в папке, определяет вид плагина:

| | **Комплект возможностей (pack)** | **Плагин с кодом** |
|---|---|---|
| Что это | Манифест и файлы данных (JSON) | Манифест и JavaScript (`main.js`) |
| Выполняет код | Никогда | Да, в изолированном процессе-песочнице |
| Подходит для | Цветовых тем, сниппетов, языков интерфейса, включения встроенных функций | Кнопок, вкладок ответа, команд палитры, изменения запроса перед отправкой, реакции на ответ |
| Разрешения | Не нужны | Запрашиваются у пользователя при включении |
| Главное поле | `"capabilities": [...]` | `"main": "main.js"` и `"contributes": {...}` |
| Примеры | [`my-theme-pack`](examples/my-theme-pack), [`my-snippets`](examples/my-snippets) | [`hello-toast`](examples/hello-toast), [`response-inspector`](examples/response-inspector), [`request-id`](examples/request-id) |

Если нужны только данные (тема, сниппеты) — делайте комплект. Если нужно поведение — плагин с кодом.

## 2. Быстрый старт: первый плагин за пять минут

Соберём [`hello-toast`](examples/hello-toast) — кнопку в заголовке окна, которая здоровается.

**1. Создайте папку** с именем, в точности равным id плагина:

```
hello-toast/
├── plugin.json
└── main.js
```

**2. `plugin.json`** — манифест:

```json
{
  "id": "hello-toast",
  "name": "Hello Toast",
  "version": "1.0.0",
  "apiVersion": 1,
  "description": "The smallest code plugin: a titlebar button that shows a toast.",
  "main": "main.js",
  "permissions": [],
  "contributes": {
    "buttons": [
      { "id": "hello", "label": "Привет", "icon": "sparkle", "location": "titlebar", "tooltip": "Сказать привет" }
    ]
  }
}
```

**3. `main.js`** — обработчик:

```js
relay.on('button:hello', () => {
  relay.toast('Привет из плагина!', 'ok')
})
```

**4. Установите.** Упакуйте папку в архив (`hello-toast.zip`, внутри `hello-toast/plugin.json` или
`plugin.json` в корне архива), затем в Relay откройте **Настройки → Плагины → «Выбрать плагин на
компьютере…»** и выберите архив. Только что установленный плагин с кодом всегда **выключен** —
включите его переключателем «Включить и разрешить».

**5. Нажмите кнопку ✨** в заголовке окна — появится приветствие.

Вместо архива плагин с кодом можно просто скопировать в его папку плагинов: Relay следит за ней и
подхватывает изменения за секунду (правки `main.js` действуют со следующего нажатия). Комплект,
скопированный в свою папку, начинает работать только после того, как его один раз добавят через
«Выбрать плагин на компьютере…» (диалог открывается именно в этой папке):

| ОС | Плагины с кодом | Комплекты возможностей |
|---|---|---|
| Windows | `%APPDATA%\Relay\relay-data\plugins\` | `resources\plugins\` в папке установки |
| macOS | `~/Library/Application Support/Relay/relay-data/plugins/` | `Relay.app/Contents/Resources/plugins/` |
| Linux | `~/.config/Relay/relay-data/plugins/` | `resources/plugins/` в папке установки |

Из любого другого места комплект подключается так же: выберите его `plugin.json` или `.zip` в
«Выбрать плагин на компьютере…» — Relay скопирует его куда нужно и сразу включит.

## 3. Комплекты возможностей: темы, сниппеты, языки

### 3.1 Манифест

```json
{
  "id": "my-theme-pack",
  "name": "My Theme Pack",
  "description": "Показывается в Настройках → Плагины",
  "version": "1.0.0",
  "capabilities": ["themes.extra"]
}
```

`id` совпадает с именем папки и состоит из строчных латинских букв, цифр и `-`. Комплект должен
объявить хотя бы одну возможность; неизвестные возможности игнорируются.

| Возможность | Файл данных | Что добавляет |
|---|---|---|
| `themes.extra` | `themes.json` | Цветовые темы в Настройках → Внешний вид |
| `snippets` | `snippets.json` | Панель сниппетов на вкладке Scripts |
| `i18n.extra` | `locales/<код>.json` + `"locales": [...]` | Языки интерфейса |
| `protocol.websocket`, `protocol.sse`, `protocol.socketio`, `protocol.mqtt`, `protocol.grpc` | — | Включают встроенные протоколы |
| `ai`, `auth.advanced`, `panes.extra`, `backup.extra`, `codegen.extra` | — | Включают встроенные функции |

Одну возможность могут нести несколько комплектов: сниппеты и темы всех включённых комплектов
объединяются.

### 3.2 Комплект тем — `themes.json`

```json
{
  "themes": [
    {
      "id": "mint",
      "name": "Mint",
      "description": "Dark teal with a mint accent.",
      "accent": "#2ee6a8",
      "variants": {
        "dark":  { "--bg-0": "#0d1716", "--tx-0": "#e8fbf4", "...": "..." },
        "light": { "--bg-0": "#f4f1ea", "--tx-0": "#1f2640", "...": "..." }
      }
    }
  ]
}
```

- В `variants` может быть `dark`, `light` или оба. Тема с обоими вариантами следует
  переключателю «Тёмная / Светлая / Системная»; тема с одним вариантом всегда использует его.
- `accent` задаёт акцентный цвет (кнопки, фокус, выделение); оттенки наведения и нажатия Relay
  вычисляет сам. Пользователь может потом выбрать другой акцент.
- Значения должны быть цветами или простыми числами: `#hex`, `rgb()/rgba()`, `hsl()`, `oklch()`,
  `oklab()`, `lab()`, `lch()`, `hwb()`, ключевые слова, `12px`/`1.5`. Всё остальное (например,
  `url(...)`) отбрасывается при чтении файла. До 40 тем в комплекте, до 80 переменных в варианте.

Переменные, которые можно задать (все необязательны — незаданные остаются как в Relay):

| Переменная | Что красит |
|---|---|
| `--bg-0` … `--bg-3` | окно, панели и сайдбар, поверхности и карточки, приподнятые элементы и поля ввода |
| `--bg-hover`, `--bg-active` | фон при наведении и нажатии (обычно полупрозрачный) |
| `--line`, `--line-2` | рамки и более заметные разделители |
| `--tx-0` … `--tx-3` | основной, вторичный, приглушённый и самый бледный текст |
| `--code-bg` | редакторы кода и блоки кода — цвета редактора вычисляются из неё и переменных `--c-*` |
| `--c-key`, `--c-str`, `--c-num`, `--c-bool`, `--c-null`, `--c-punct` | подсветка JSON |
| `--m-get`, `--m-post`, `--m-put`, `--m-patch`, `--m-delete`, `--m-head`, `--m-options` | цвета методов HTTP |
| `--s-2xx`, `--s-3xx`, `--s-4xx`, `--s-5xx` | цвета кодов ответа |
| `--accent-fg` | текст на кнопках акцентного цвета (для светлого акцента ставьте тёмный) |

Совет: в режиме разработки (`npm run dev`, DevTools — Ctrl+Shift+I) переменные можно править прямо
на `<html>` и затем перенести в `themes.json`. 15 тем встроенного `plugins/theme-pack` — хороший
образец.

### 3.3 Комплект сниппетов — `snippets.json`

```json
{
  "snippets": [
    {
      "id": "team-envelope",
      "group": "Team",
      "label": "Response follows our { data, error } envelope",
      "phase": "test",
      "code": "pm.test(\"Envelope\", function () {\n    const body = pm.response.json();\n    pm.expect(body).to.have.property(\"data\");\n});\n"
    }
  ]
}
```

| Поле | Правила |
|---|---|
| `id` | строчный идентификатор, уникальный в комплекте |
| `label` | до 120 символов |
| `group` | необязательный заголовок группы в панели |
| `phase` | `pre` (Pre-request), `test` (Post-response) или `both` |
| `code` | до 20 000 символов; вставляется в конец скрипта |

Сниппеты выполняются в песочнице скриптов Relay, которая предоставляет скриптовый API `pm.*`: `pm.test`,
`pm.expect`, `pm.response` (`code`, `status`, `json()`, `text()`, `headers.get()`,
`responseTime`, `to.have.status()`, `to.have.header()`), `pm.request` (`url`, `method`,
`headers`), `pm.environment`, `pm.globals`, `pm.collectionVariables`, `pm.variables`,
`pm.cookies`, `pm.sendRequest`.

### 3.4 Комплект языка

Добавьте `"capabilities": ["i18n.extra"]` и `"locales": ["it"]`, а каталог положите в
`locales/it.json`. **Ключи — исходные русские строки**, значения — ваш перевод; за основу удобно
взять `src/renderer/locales/en.json`. Недостающие ключи показываются по-английски.

## 4. Плагины с кодом

### 4.1 Поля манифеста

| Поле | Обязательно | Правила |
|---|---|---|
| `id` | да | `^[a-z0-9][a-z0-9-]{1,63}$`, совпадает с именем папки |
| `name`, `version` | да | `version` в виде `x.y.z` |
| `description`, `author` | нет | показываются на карточке плагина |
| `main` | нет | имя файла обработчиков (по умолчанию `main.js`, ≤ 512 КБ) |
| `apiVersion` | нет | `1`; плагин для более новой версии приложения не запустится вовсе, а не наполовину |
| `permissions` | нет | см. [4.4](#44-разрешения) |
| `contributes.buttons` | нет | ≤ 10: `{ id, label, icon?, tooltip?, location }`, `location` — `response-toolbar`, `titlebar` или `sidebar` |
| `contributes.panels` | нет | ≤ 10 вкладок ответа: `{ id, label, icon?, location: "response-tab", interactive? }` |
| `contributes.commands` | нет | ≤ 20 команд в палитре (Ctrl+K): `{ id, title, icon? }` |
| `contributes.themes` | нет | ≤ 10: `{ id, label, base: "dark"\|"light", vars }` — применяются с карточки плагина |
| `contributes.events` | нет | `response`, `request` (нужно `request:write`), `workspace`, `collection` |
| `config` | нет | ≤ 20 полей `{ key, label, type: "string"\|"secret", placeholder?, description? }` |
| `i18n` | нет | `{ "en": { "hello": "Hello" } }`; подпись вида `%hello%` будет переведена |

Иконки — имена иконок Relay: `send`, `sparkle`, `play`, `copy`, `download`, `upload`, `info`,
`code2`, `terminal`, `link`, `bolt`, `key`, `mail`, `refresh`, `eye`, `settings`, … — для
неизвестного имени рисуется значок по умолчанию.

### 4.2 API `relay`

`main.js` выполняется заново на каждое событие и регистрирует обработчики в глобальном объекте
`relay`:

| Что | Разрешение | Назначение |
|---|---|---|
| `relay.on(event, fn)` | — | зарегистрировать обработчик (`fn` может быть `async`) |
| `relay.toast(message, kind?)` | — | всплывающее сообщение от имени плагина; `kind` — `ok` или `error` |
| `relay.log/info/warn/error(...)`, `console.*` | — | строки журнала, видны на карточке плагина |
| `relay.config` | — | значения ваших полей `config` (секреты расшифровываются только здесь) |
| `relay.fetch(url, init?)` | `net` или `net:<host>` | HTTP-запрос: `{ ok, status, headers.get(), text(), json() }`; ≤ 5 за событие, 10 с, 1 МБ |
| `relay.storage.get/set/delete/has/keys` | `storage` | собственное хранилище ключ-значение (≤ 100 ключей по 8 КБ) |
| `relay.request.setUrl/setMethod/setHeader/removeHeader` | `request:write` | изменить запрос в обработчике `request` |
| `relay.panel.set(html)` | — | HTML вкладки (в обработчике `panel:<id>`) |
| `relay.clipboard.writeText(text)` | `clipboard` | скопировать текст для пользователя |
| `setTimeout` / `clearTimeout` | — | короткие таймеры (≤ 5 с) |

Нет `require`, `process`, DOM и `eval`. Между событиями ничего не сохраняется, кроме
`relay.storage`.

### 4.3 События и контекст

| Ключ события | Когда срабатывает | Что в `ctx` |
|---|---|---|
| `button:<id>` (или `button`) | нажата ваша кнопка | `buttonId`, `request?`, `response?` |
| `panel:<id>` (или `panel`) | открыта или обновлена ваша вкладка ответа | `panelId`, `request?`, `response?`, `message?` |
| `command:<id>` (или `command`) | выполнена ваша команда палитры | `commandId`, `request?`, `response?` |
| `request` | перед каждой отправкой — **задерживает отправку**, лимит 5 с | `request?` |
| `response` | после каждого ответа (ручная отправка и раннер) | `request?`, `response?` |
| `workspace` | сменилось рабочее пространство | `workspace` |
| `collection` | коллекции сохранены | `history?` |

`request` — это `{ method, url, headers: [{ key, value }] }`, `response` — `{ status, statusText,
headers: [[имя, значение], …], contentType, bodyText?, truncated?, sizeBytes, timeMs, finalUrl }`.
Они приходят, только если у плагина есть `request:read` / `response:read`. Заголовки с учётными
данными (Authorization, Cookie, ключи API…) и все значения параметров запроса замаскированы.

**Вкладки.** HTML вкладки показывается в изолированном iframe: без скриптов, без сети, картинки
только как `data:`. С `"interactive": true` скрипты разрешены, но у фрейма нулевой источник: его
единственный канал — `parent.postMessage(data, '*')`, который приходит в обработчик как
`ctx.message`; HTML, заданный в ответ, заменяет содержимое фрейма.

Пример: [`response-inspector`](examples/response-inspector) рисует вкладку со сводкой ответа.

**Изменение запросов.** [`request-id`](examples/request-id) добавляет заголовок к каждому запросу:

```js
relay.on('request', () => {
  relay.request.setHeader(relay.config.headerName || 'X-Request-Id', uuid())
})
```

Хук `request` может менять адрес, метод и заголовки. Если он направит запрос на другой источник,
изменение отклоняется, пока у плагина нет `net` для этого хоста, — и даже тогда из запроса
убираются авторизация пользователя, секретные заголовки, тело и параметры.

### 4.4 Разрешения

Объявляйте только то, чем пользуетесь: перед включением пользователь видит каждое разрешение
простой фразой.

| Разрешение | Что даёт |
|---|---|
| `net` | `relay.fetch` к любому хосту |
| `net:<host>` | `relay.fetch` к одному хосту (`api.example.com`, `*.example.com`, можно с `:порт`) — проверяется на каждом редиректе |
| `request:read` | (замаскированный) запрос в `ctx.request` |
| `response:read` | ответ в `ctx.response` (тело до 200 КБ) |
| `request:write` | `relay.request.*` в обработчике `request`; обязательно для события `request` |
| `storage` | `relay.storage.*` |
| `clipboard` | `relay.clipboard.writeText` |
| `history:read` | 25 последних записей истории (адреса замаскированы) в `ctx.history` |

Если новая версия плагина просит больше разрешений, Relay выключает его и показывает новые
разрешения, пока пользователь не подтвердит их снова.

### 4.5 Ограничения

| Что | Предел |
|---|---|
| синхронный код | 3 с |
| асинхронный обработчик | 10 с (хук `request` — 5 с) |
| весь запуск | 15 с, затем процесс завершается |
| `main.js` / `plugin.json` | 512 КБ / 64 КБ |
| `relay.fetch` | 5 вызовов за событие, по 10 с, ответ до 1 МБ |
| параллельные запуски | 2 процесса плагинов; события `response` одного плагина схлопываются |

## 5. Упаковка и распространение

- Распространяйте `.zip`, в котором `plugin.json` лежит в корне или в одной папке верхнего уровня.
  Relay проверяет размер и манифест, пишет файлы только в `plugins/<id>/` и устанавливает плагины с
  кодом **выключенными**.
- Повышайте `version` в каждом выпуске. Установка того же `id` заменяет старые файлы (и снова
  начинается с выключенного состояния — пользователь заново одобряет код).
- Положите рядом с `plugin.json` короткий README: что делает плагин и зачем ему каждое разрешение.

## 6. Отладка

- Карточка плагина в **Настройки → Плагины** показывает последний запуск: время, событие,
  длительность, ошибку и хвост журнала. Не стесняйтесь писать `relay.log(...)`.
- Если обработчик выбросил исключение, появится сообщение «Плагин <имя>: <ошибка>».
- В режиме разработки (`npm run dev`) журнал запусков кнопок виден и в консоли DevTools.
- Relay перечитывает плагин при изменении его папки; повторное открытие Настройки → Плагины
  пересканирует папку.

| Сообщение | Причина |
|---|---|
| `id "…" must equal the plugin folder name "…"` (плагин с кодом) / `id в манифесте не совпадает с именем папки` (комплект) | переименуйте папку или id |
| `unknown permission "..."` | опечатка в `permissions` |
| `unknown event` | в `contributes.events` что-то кроме `response`, `request`, `workspace`, `collection` |
| `the 'request' event requires the 'request:write' permission` | добавьте разрешение |
| `relay.fetch requires the 'net' permission` / `relay.fetch: host not allowed by granted permissions` | добавьте `net` / `net:<host>` |
| темы нет во «Внешнем виде» | комплект выключен или все значения отброшены проверкой цветов |

## 7. Чего плагин не может никогда

Код плагина выполняется в отдельном процессе с отключённой генерацией кода, и ему доступен только
объект `relay`: ни файловой системы, ни Node, ни Electron, ни доступа к окну или другим плагинам.
Он никогда не видит ключей AI-провайдеров, сохранённых секретов приложения и данных других
плагинов. Сеть, запрос и ответ доступны только через разрешения, которые выдал пользователь.
Полная модель угроз — в [docs/PLUGINS.ru.md](../PLUGINS.ru.md#8-модель-безопасности).

## 8. Чек-лист перед публикацией

- [ ] имя папки совпадает с `id`; `version` повышена
- [ ] только действительно нужные разрешения, и в README сказано зачем
