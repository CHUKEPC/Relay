# ARCHITECTURE.md

*[English version](ARCHITECTURE.md)*

## Модель процессов (Electron)

Три контекста, строгое разделение:

- **main** (Node.js): жизненный цикл приложения, окна, движок HTTP-запросов, клиент AI-провайдеров,
  хранилище/репозитории, хранение секретов и все обработчики IPC. Именно здесь выполняются сетевые вызовы —
  **браузерный CORS здесь не действует**, и ради этого мы и используем Electron.
- **preload**: единственный мост. Через `contextBridge.exposeInMainWorld('api', …)` открывает рендереру
  **типизированный, минимальный** интерфейс. Никакого сырого `ipcRenderer`, никаких утечек глобальных объектов Node.
- **renderer** (React): чистый UI. Общается с main исключительно через `window.api`.

Базовые требования безопасности (не обсуждаются): `contextIsolation: true`, `nodeIntegration: false`,
`sandbox: true` там, где это возможно, `webSecurity: true`. Удалённый контент никогда не загружается в главное
окно; единственные «удалённые» вещи — это (а) исходящие API-вызовы из main и (б) **предпросмотр** ответа в песочнице,
отрисованный в изолированном `<webview>`/`<iframe sandbox>` с отключёнными скриптами.

```
┌─────────────┐  window.api (typed)   ┌──────────────┐   IPC    ┌──────────────────────┐
│  renderer   │ ───────────────────►  │   preload    │ ───────► │        main          │
│  (React UI) │ ◄───────────────────  │ contextBridge│ ◄─────── │ http · ai · storage  │
└─────────────┘   events / responses  └──────────────┘          └──────────────────────┘
                                                                  outbound HTTPS (no CORS)
```

## IPC-контракт

Определяется один раз в `src/shared/ipc-contract.ts` и используется в preload, main и рендерере. Каналы
(примерные — окончательно фиксируются в ходе сборки):

| Канал | Направление | Назначение |
|---------|-----------|---------|
| `request:send` | renderer→main (запрос/ответ) | выполнить HTTP-запрос; возвращает `ResponseResult` |
| `request:cancel` | renderer→main | отменить выполняющийся запрос по id |
| `request:stream` | main→renderer (события) | необязательные фрагменты потоковой передачи/прогресса |
| `ai:chat` | renderer→main, **потоковый** | выполнить AI-запрос на генерацию; отправляет события с приращениями (delta) |
| `ai:cancel` | renderer→main | отменить AI-поток |
| `ai:listModels` | renderer→main | получить список моделей провайдера |
| `secrets:set` / `secrets:get` / `secrets:delete` | renderer→main | зашифрованные API-ключи через safeStorage (рендерер работает только со *ссылками* на ключи и никогда не получает обратно их значения) |
| `storage:load` / `storage:save` | renderer→main | коллекции, окружения, история, вкладки, настройки |
| `data:import` / `data:export` | renderer→main | импорт Postman/OpenAPI/cURL, экспорт коллекций |
| `app:dialog` | renderer→main | нативные диалоги открытия/сохранения файлов |

Схема потоковой передачи: рендерер вызывает `ai:chat` со `streamId`; main отправляет события
`ai:chat:delta:<streamId>` и завершающее `ai:chat:done` / `ai:chat:error`. Тот же подход можно
использовать для больших HTTP-загрузок.

## HTTP-движок (`src/main/http`)

Чистое, тестируемое ядро. Сигнатура:

```ts
runRequest(spec: RequestSpec, opts: RunOptions): Promise<ResponseResult>
```

- **Вход `RequestSpec`** (к моменту попадания в main переменные уже подставлены, ЛИБО main сам выполняет
  подстановку по снимку окружения — выберите одно и придерживайтесь его; рекомендуется: рендерер отправляет
  сырой запрос + карту разрешённых переменных, а main выполняет подстановку, чтобы секреты не возвращались в рендерер).
  Поля: method, url, query-параметры, заголовки, тело (типизированное объединение: none/raw/urlencoded/formdata/
  binary/graphql), авторизация, настройки (timeout, followRedirects, rejectUnauthorized).
- **Движок**: Node `undici`/`fetch` (или `axios`) с:
  - `AbortController` для отмены/таймаута.
  - ручной обработкой редиректов, когда это нужно (чтобы записать цепочку), — или `redirect: 'follow'` с ограничением.
  - `multipart/form-data`, собираемым через `FormData`/потоки; файловые поля читаются с диска по путям.
  - TLS: учитывается `rejectUnauthorized` (переключатель проверки SSL).
  - **Тайминги**: фиксация начало → DNS/соединение/TTFB → конец; отчёт об общем времени в мс (разбивка — по мере возможности).
  - **Размер**: байты тела ответа + заголовков.
  - хранилищем cookie (P1) на `tough-cookie`.
- **Выход `ResponseResult`**: status, statusText, заголовки (массив пар), тело (текст + определённый
  contentType + base64 для бинарных данных), тайминги, размер, редиректы, ошибка (структурированная), если есть.

## AI-клиент (`src/main/ai`)

Не зависит от провайдера. Адаптер `Provider` приводит всё к единому потоковому интерфейсу чата:

```ts
interface Provider {
  id: string
  chat(messages: ChatMessage[], opts): AsyncIterable<Delta>   // yields text deltas (+ tool calls)
  listModels?(): Promise<ModelInfo[]>
}
```

Адаптеры: `openai`, `anthropic`, `openrouter`, `openai-compatible` (собственный базовый URL: Ollama, LM
Studio и т. д.). Потоковая передача — это SSE, который разбирается в main и пересылается рендереру как IPC-события. Точные
форматы запросов/ответов и вызов инструментов см. в [`AI_ASSISTANT.ru.md`](AI_ASSISTANT.ru.md).

API-ключи читаются из `safeStorage` только внутри main. Они **никогда** не отправляются рендереру и
**никогда** не попадают в журналы.

## Хранилище (`src/main/storage`)

Local-first, **без нативных модулей**:

- Собственный **`JsonStore`** (`src/main/storage/json-store.ts`) записывает по одному JSON-документу на ключ
  в `app.getPath('userData')/relay-data`:
  - уровень приложения: `settings`, `providers`, `plugins`, `features`, `userThemes`;
  - уровень рабочего пространства (`ws/<id>/`): `collections`, `environments`, `globals`, `history`, `tabs`, `cookies`.
  - Модель в памяти + **отложенная (debounced)** атомарная запись (запись во временный файл, затем переименование). Документ, который не удаётся
    разобрать, откладывается в сторону как `<key>.json.corrupt-<ts>` прежде, чем что-либо будет записано поверх него, а каждая
    папка рабочего пространства хранит `workspace.json`, чтобы повреждённый список рабочих пространств можно было восстановить.
- **Секреты** (AI-ключи, секреты авторизации запросов) — через Electron `safeStorage` → зашифрованные блобы с ключом в виде
  стабильного id ссылки; на диск попадает только шифротекст.
- Схема/версионирование: каждый документ несёт `version`; предусмотрите хук миграции с прямой совместимостью.

> SQLite существует только как формат резервного копирования/экспорта, через `sql.js` на чистом WASM (`src/main/sqlite`).
> Нативные модули вроде `better-sqlite3` по-прежнему под запретом: пересборки снижают надёжность сборки.
>
> Каждый путь восстановления (JSON, ZIP, SQLite) пропускает прочитанное через функции-приёмники из
> `src/shared/backup-shape.ts`, поэтому чужой или отредактированный вручную файл никогда не заменит рабочее пространство
> объектами, которые UI не может отрисовать.

## Состояние рендерера (`src/renderer/store`, Zustand)

Предлагаемые срезы: `requestStore` (открытые вкладки + черновик активного запроса), `collectionsStore`,
`environmentsStore`, `historyStore`, `responseStore`, `aiStore`, `settingsStore`, `uiStore`
(тема, раскладка панелей). Сохранение делегируется main через IPC, а не хранится только в `localStorage`.

## Горячие клавиши (`src/renderer/lib/keymap.ts`)

Одна таблица (`KEY_ACTIONS`) владеет каждым действием, его подписью и сочетанием по умолчанию; пользовательские переопределения хранятся в
`SettingsDoc.keybindings` (`''` отключает действие). Сочетания определяются по ФИЗИЧЕСКОЙ клавише (`e.code`),
поэтому работают и в нелатинской раскладке, а оба окна слушают события в **фазе перехвата (capture)** — Monaco, диалоги
Radix и обычные поля ввода останавливают keydown до того, как он дойдёт до `window`, из-за чего раньше
сочетание срабатывало, только если фокус случайно находился на фоне страницы. Три следствия, о которых стоит
помнить:

- Экран горячих клавиш во время записи сочетания вызывает `setRecordingShortcut(true)`, иначе приложение выполнило бы
  то самое сочетание, которое переназначают.
- AltGr (который в раскладках, где он есть, приходит как Ctrl+Alt) игнорируется только для элемента, принимающего
  ввод текста, поэтому `Ctrl+Alt+<key>` остаётся доступным как сочетание везде, кроме таких элементов.
- **`Ctrl+Alt+<digit>` не годится как сочетание по умолчанию.** Измерено с реальной эмуляцией нажатий в Windows 11:
  `Ctrl+Alt+1/2/3` вообще не доходят до окна (резидентные программы регистрируют их на уровне системы),
  а `Ctrl+Alt+4/8/9` доходят — причём в русской раскладке `Ctrl+Alt+8` ещё и печатает `₽`, потому что Windows
  передаёт Ctrl+Alt раскладке как AltGr. Поэтому пресеты панелей назначены на `Ctrl+Shift+<digit>`, а
  разбиения — на `Ctrl+\` / `Ctrl+Shift+\`; проверено, что все они приходят с неизменённым `e.code`
  в кириллической раскладке. Сочетание, перехваченное другой программой, невозможно вернуть
  изнутри приложения; каждое действие с панелями также доступно из меню панели, и в FAQ об этом сказано.

Стандартное меню Electron удаляется в main (`Menu.setApplicationMenu(null)`): в безрамочном окне оно невидимо, но его
акселераторы срабатывали первыми — Ctrl+W закрывал окно вместо вкладки.
Экран справки и вводный тур берут подсказки по клавишам из той же таблицы, поэтому они не могут устареть.

## Подстановка переменных

Единый резолвер, используемый везде: получив строку и объединённую область переменных (коллекция → окружение →
глобальные, синтаксис `{{var}}` и несколько встроенных вроде `{{$guid}}`, `{{$timestamp}}`,
`{{$randomInt}}`), он возвращает итоговую строку и список неразрешённых имён для пометки в UI.

## Песочница скриптов (P1)

Pre-request- и тестовые скрипты выполняются в **изолированном дочернем процессе** в контексте Node `vm` с замороженным
объектом `pm` из белого списка — без `require`, без `process`, без fs. Доступны `pm.environment`, `pm.globals`,
`pm.variables`, `pm.request`, `pm.response`, `pm.test`, `pm.expect`. Вывод `console.log` и результаты тестов
перехватываются и возвращаются рендереру.

Дочерние процессы (и песочница скриптов, и песочница плагинов) запускают **собственный бандл** —
`out/main/sandbox.js` из `src/main/sandbox-entry.ts`, путь к которому во время выполнения определяет
`src/main/sandbox-path.ts`. Они не должны запускать главный бандл приложения: дочерний процесс — это исполняемый файл Electron
с `ELECTRON_RUN_AS_NODE=1`, где встроенного модуля `electron` не существует, поэтому `require('electron')` верхнего уровня
в главном бандле выбрасывает исключение. В режиме разработки этот require всё же разрешается —
npm-пакет `electron` лежит на диске, — поэтому форк главного бандла казался рабочим, хотя в собранном приложении
КАЖДЫЙ скрипт и КАЖДЫЙ плагин мгновенно падал с «Script sandbox stopped».
Точка входа песочницы подтягивает два хоста и ничего, что касается Electron (все импорты `electron`
в этом графе модулей — `import type`); сборка, в которой это сломается, выдаст себя появлением
`require("electron")` внутри `out/main/chunks/*`.

Дочерний процесс, чисто завершивший запуск, остаётся **тёплым** для следующего скрипта (`keepWarm`), потому что
форк Electron в роли Node стоит несколько сотен миллисекунд процессорного времени, а запуск коллекции платит эту цену дважды
на каждый запрос. Дочерний процесс выводится из работы, а не используется повторно, если его запуск завершился по таймауту, упал или оставил незавершённую
асинхронную работу.

## Сетевое поведение

Исходящие соединения выполняются в рамках действий пользователя. Что в этом участвует:

- **Никакой фоновой сетевой активности.** Автоматической проверки обновлений нет (`src/main/update` запускается только
  по кнопке в разделе «О приложении»), нет телеметрии, нет отправки отчётов о сбоях.
- **CSP** на каждом ответе сессии по умолчанию (`contentSecurityPolicy()` в `src/main/index.ts`):
  `img-src 'self' data: blob:`, `connect-src 'self'` и так далее. Она применяется и к странице `file://`
  (проверено), поэтому ни UI, ни HTML-предпросмотр ответа не могут загрузить удалённый ресурс.
- **Усиление защиты сессии** (`isolateSession()`): проверка орфографии выключена (иначе она загружала бы словари),
  все запросы разрешений отклоняются, кроме чтения/записи буфера обмена, и задан `--dns-prefetch-disable`.
- **У исходящего трафика есть владелец**: HTTP-движок, realtime/gRPC-клиенты, получение токена OAuth и
  вход через браузер (loopback-слушатель, существующий только пока пользователь входит), AI-клиент
  (только с AI-комплектом) и плагины с разрешением `net`.

## Прикрепляемые панели (`src/renderer/lib/dock.tsx`)

Боковая панель, панель ответа и консоль запросов используют одну модель закрепления: `left | right |
bottom | top | float` (у боковой панели и консоли нет `top`). `useDockDrag` превращает нажатие на заголовок
панели в сеанс перетаскивания: разрешённые края контейнера подсвечиваются, и отпускание на них закрепляет
панель; в любом другом месте перемещение отменяется. Плавающей панель делает только кнопка, а плавающая
панель при перетаскивании за заголовок просто двигается. Зона запроса тоже перетаскивается
(`BuilderDockContext`, ручка в заголовке запроса) и ставит ответ на противоположный край. `lib/dock-swap.ts`
меняет местами боковую панель и ответ, касающиеся одного края окна, вместо того чтобы складывать их рядом.
Положение боковой панели хранится в UI-сторе (localStorage); положение панели ответа — своё для каждой панели
(`PaneLeaf.respDock` / `respFloat`, перенесено из поля `layout` версии 1.2). Панели, отрисовывающие
строку состояния, получают свои элементы управления через `PaneDockContext`, а не через props.
`--panel-head-h` держит все заголовки панелей одной высоты, чтобы их нижние линии совпадали.

Файлы, брошенные из системы, обрабатывают `app/FileDropZone.tsx` → `lib/file-drop.ts` (выбор обработки по
каждому файлу, затем тот же `lib/import-apply.ts`, что и в диалоге «Импорт»); main запрещает любую
навигацию на `file://`, кроме собственной страницы приложения.

## Режим для слабых ПК

`SettingsDoc.lowPowerMode` читается main до готовности приложения (`lowPowerRequested()`), потому что
решение о GPU нельзя изменить позже: аппаратное ускорение выключено, программная композиция, режим
слабого устройства Chromium, без плавной прокрутки. Рендерер при гидратации помечает `<html data-low-power>`;
`styles/low-power.css` убирает анимации, размытие и тени, а `CodeEditor` отрисовывает
`CodeEditorPlain` (textarea с тем же автодополнением `{{` из `lib/var-suggest.ts`), поэтому
чанк Monaco и его воркеры вообще не загружаются.

## Темы

CSS-переменные в `:root` и `.dark`, начальные значения берутся из `design/tokens`. Tailwind читает их через
`theme.extend.colors`, ссылаясь на переменные. Выбор темы сохраняется в настройках; режим `system`
следует `nativeTheme`.

## Упаковка

Конфигурация `electron-builder` (`electron-builder.yml`): `win` → `nsis`; `mac` → `dmg` + `zip`
(entitlements для hardened runtime — заглушки); `linux` → `AppImage` + `deb`. Иконка приложения берётся из
`design/assets`. `npm run build:{win,mac,linux}` служит обёрткой над этим.
