# FEATURES.md — список возможностей

*[English version](FEATURES.md)*

Возможности десктопного API-клиента Relay, разбитые на уровни приоритета. **P0 обязан работать** в первой сборке. P1 следует попытаться реализовать в той же сборке,
и ожидается, что в основном он будет работать. P2 — по мере возможности / на будущее. Всё, что требует серверного бэкенда
(командная синхронизация, облачные рабочие пространства), **вне рамок проекта** — это приложение **local-first**.

Обозначения: `[x]` готово · `[~]` частично · `[ ]` ещё нет. Обновлено в соответствии с реализованной сборкой.

## P0 — Ядро (всё реализовано и проверено)

- [x] Выбор метода: GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS (+ произвольный через движок).
- [x] Адресная строка с подсветкой `{{variable}}` и значением при наведении прямо в строке (источник + значение).
- [x] Редактор query-параметров: ключ / значение / описание / флажок включения; двусторонняя синхронизация с URL.
- [x] Path-переменные (в стиле `:id`) автоматически определяются по URL и доступны для редактирования.
- [x] Редактор заголовков: ключ / значение / включён; автодополнение имён распространённых заголовков; пояснение об автоматически добавляемых заголовках.
- [x] Типы тела:
  - [x] none
  - [x] raw с выбором языка (JSON, Text, XML, HTML, JavaScript) через Monaco; задаёт Content-Type
  - [x] `x-www-form-urlencoded` (таблица ключ/значение/включён)
  - [x] `form-data` (текстовые **и** файловые поля; выбор файла)
  - [x] binary (загрузка одного файла)
  - [x] GraphQL (редактор запроса + редактор переменных)
- [x] Действие «Beautify»/форматирование для тел JSON/XML.

### Авторизация

- [x] Bearer Token
- [x] Basic Auth (имя пользователя/пароль → base64)
- [x] API Key (в заголовок или в query-параметр)
- [x] Наследование авторизации от родительской коллекции/папки (с обходом дерева)
- [x] OAuth 2.0 (получение токена + подстановка), Digest (по мере возможности) — см. P1

### Отправка и ответ

## P1 — Высокая ценность (предпринято в этой сборке)

- [x] **Pre-request-скрипты** и **тесты** в изолированной (отдельный дочерний процесс) среде выполнения `pm.*`:
      `pm.environment`, `pm.globals`, `pm.variables` (включая локальную область `.set/.unset`),
      `pm.collectionVariables`, `pm.iterationData`, `pm.request`, `pm.response`, `pm.cookies`,
      `pm.sendRequest`, `pm.visualizer`, `pm.test` и широкое подмножество chai для `pm.expect`
      (`.members/.oneOf/.keys/.closeTo/.throw/.nested.property/…`). Pre-request- и тестовые скрипты **уровня коллекции и папки**
      выполняются сверху вниз вокруг запроса. Результаты — на вкладке тестов с консолью.
- [x] **Импорт**: Postman Collection v2.1, OpenAPI 3.x **и Swagger 2.0** (JSON **или YAML**),
      **HAR**, **Insomnia v4** и cURL (вставкой или из файла).
- [x] **Экспорт**: коллекция как JSON Postman v2.1; всё рабочее пространство как переносимый `.sqlite`.
- [x] **Генерация кода** (16 целевых языков): cURL, raw HTTP, JavaScript (fetch) и Python (requests) в
      ядре; Node, Go, **Java (OkHttp), C# (HttpClient), PHP (cURL), Ruby (Net::HTTP), Swift
      (URLSession), Kotlin (OkHttp), Rust (reqwest), PowerShell, HTTPie, wget** с комплектом
      `codegen-languages` (1.2).
- [x] **Вставка cURL** в адресную строку автоматически заполняет весь запрос.
- [x] **~50 динамических переменных** (`{{$randomFirstName}}`, `{{$randomEmail}}`, `{{$randomIP}}`,
      `{{$randomDatetime}}`, …) плюс `{{$guid}}/{{$timestamp}}/{{$counter}}`.
- [x] **OAuth 2.0**: client_credentials, password, authorization_code (**+ PKCE**), **refresh_token**
      и **device code** (RFC 8628); учётные данные клиента в теле или через HTTP Basic; **автообновление при 401**.
- [x] **Digest-авторизация** — полный цикл challenge/response по RFC 7616 (MD5, SHA-256 и варианты `-sess`;
      qop=auth; запасной режим по устаревшему RFC 2069). Первый запрос отправляется без авторизации; движок
      отвечает на вызов 401 `WWW-Authenticate: Digest` и повторяет запрос один раз. Покрыто модульными тестами на
      эталонных векторах из RFC. **Упреждающий режим** отправляет учётные данные уже в первом запросе, если
      realm/nonce известны.
- [x] **Менеджер cookie**: постоянное редактируемое хранилище (jar) в main (своё для каждого рабочего пространства) — автоматически
      сохраняет `Set-Cookie` и автоматически подставляет подходящие cookie (domain/path/secure/expiry) в запросы; UI
      менеджера cookie (группировка по домену; добавление/правка/удаление; очистить всё / очистить по домену). Таблица
      cookie для каждого ответа осталась.
- [x] Сохранение **примеров ответов** у запроса (сохранение текущего ответа как именованного примера;
      вкладка Examples для просмотра/восстановления/удаления; восстановление показывает сохранённый ответ без отправки;
      переносится в Postman v2.1 `item.response[]` и обратно).
- [x] **Массовое редактирование** параметров/заголовков (текстовый режим key:value; `//` отключает строку; пустые строки
      игнорируются; двустороннее преобразование без потерь, с сохранением состояния включения и описаний).
- [x] **Расширенные типы авторизации** (на чистом `node:crypto`, проверены на тестовых векторах): **JWT Bearer** (HS/RS/PS),
      **OAuth 1.0a** (HMAC-SHA1/256, PLAINTEXT), **AWS Signature v4** (включая UNSIGNED-PAYLOAD для
      multipart), **Hawk**, **Akamai EdgeGrid**, **ASAP** и **NTLM** (NTLMv2 с написанной вручную
      реализацией MD4 на чистом JS, поскольку в OpenSSL 3 её убрали; рукопожатие Type 1/2/3 выполняется внутри движка на
      пуле, принудительно ограниченном одним соединением, и отвечает на вызов 401 сообщением Type 3). Токенная
      авторизация добавляет заголовок; авторизация, привязанная к запросу, подписывается после сборки тела. **Поддерживаются все
      перечисленные схемы.**
- [x] **Тестовые сниппеты** — панель Snippets в редакторе скриптов вставляет готовые заготовки `pm.test`/`pm.expect`
      (код статуса, время ответа, тело содержит/равно/значение JSON, проверки заголовков,
      установка/чтение переменных окружения, …).
- [x] **HTTP/2** — необязательное согласование через ALPN (undici `allowH2`), переключатель в Настройки → Сеть.
- [x] **Поиск** по коллекциям/запросам; **палитра команд** (Cmd/Ctrl+K).
- [x] Горячие клавиши (отправка — Cmd/Ctrl+Enter, новая вкладка ⌘N, сохранение ⌘S, закрыть вкладку ⌘W, AI ⌘J, настройки ⌘,).
- [x] **Вызов инструментов AI**: ассистент может читать/изменять текущий запрос, задавать переменные и отправлять
      запрос — изменяющие действия и отправка требуют явного подтверждения в диалоге (переключатель автоприменения в настройках).

## P2 — реализовано локально (серверный бэкенд не нужен)

- [x] **Раннер** коллекций (N итераций + необязательный файл данных CSV/JSON). Каждая итерация привязывает одну
      строку данных как область с наивысшим приоритетом и предоставляет `pm.iterationData`; выполняет все запросы
      по порядку с pre-request/тестовыми скриптами; прогресс в реальном времени; успех/провал по каждому запросу и итерации; остановка.
      Список запуска редактируется: коллекция или папка заполняет его, флажки определяют, что выполняется, а
      стрелки задают порядок, так что произвольный набор запросов — в том числе из разных коллекций — можно
      отправить за один проход. Открывается из контекстного меню коллекции, из боковой панели («Раннер»,
      пустой, для ручного выбора) или по Ctrl/⌘+Shift+R. «Стоп при ошибке» завершает запуск на первом
      упавшем запросе или тесте, а результат можно сохранить как JSON-отчёт.
- [x] **Поиск и замена по всему рабочему пространству** (Ctrl/⌘+Shift+F): один проход по всем коллекциям,
      окружениям и глобальным переменным — имена, URL, параметры, заголовки, тела (raw, GraphQL, form),
      поля авторизации, скрипты и описания. Переключатели регистра, целого слова и регулярных выражений; область поиска
      сужается по группам полей и по охвату. Совпадения возвращаются списком с контекстом, у каждого — свой
      флажок, так что массовая правка (домен, версия API) применяется только там, где нужно. Значения секретных
      переменных никогда не участвуют. Логика чистая и покрыта модульными тестами
      (`src/renderer/lib/find-replace.ts`).
- [x] Клиенты **WebSocket** + **SSE** (движки в главном процессе на базе undici; поток IPC-событий для каждого соединения;
      собственные заголовки рукопожатия; отправка по WS + бинарные фреймы в base64; разбор SSE `event/data/id/retry`
      с автоматическим переподключением + `Last-Event-ID`). Переключатель режима в адресной строке; панель
      сообщений/событий + поле для отправки.
- [x] **Заголовки запроса по умолчанию**: `User-Agent: Relay/<version>`, `Accept: */*` и
      `Accept-Encoding: gzip, deflate, br` отправляются, если пользователь не задал какой-либо из них сам (пустое значение
      убирает заголовок). undici сам не отправляет ни одного из них, поэтому раньше запрос приходил, не неся ничего,
      кроме `Host`, — а на такое WAF, API-шлюзы и ряд фреймворков отвечают 400 или 403.
- [x] **Литеральные фигурные скобки сохраняются в URL**: парсер WHATWG экранирует `{`/`}` в `%7B`/`%7D`, поэтому API,
      принимающий литеральный `{id}`, — или URL, в котором остался неразрешённый `{{var}}`, — раньше получал
      искажённый адрес. Теперь скобки отправляются как есть, как это делают браузеры, а при отправке с неразрешёнными
      переменными приложение прямо сообщает об этом, вместо того чтобы оставлять объяснение ответу 400.
- [x] **Просмотр переменных** (глаз в заголовке окна): что на самом деле использует следующий запрос —
      переменные коллекции, окружения и глобальные в порядке приоритета, перекрытые имена зачёркнуты,
      секреты скрыты за кнопкой показа, есть фильтр и копирование. Токен, записанный pre-request-скриптом,
      виден без открытия редактора окружения.
- [x] **Автодополнение `{{`**: ввод двух фигурных скобок в любом поле запроса (URL, параметры,
      заголовки, авторизация) или в редакторе (тело, скрипты) открывает список переменных, которые действительно
      доступны в текущей области видимости — переменные коллекции, окружения, глобальные с текущими значениями (секреты замаскированы), а затем
      встроенные динамические. Список сужается по мере ввода имени, ↑↓ выбирают, Enter/Tab вставляют
      целиком `{{name}}`, Esc скрывает список; выбор внутри существующей ссылки заменяет её, а не
      вкладывает новую. Имя, определённое в нескольких областях, показывается один раз, с указанием той области,
      которая побеждает. Логика сопоставления и ранжирования чистая и покрыта модульными тестами (`src/renderer/lib/var-suggest.ts`),
      а провайдер Monaco (`var-completion.ts`) использует ту же функцию.
- [x] **pm.sendRequest понимает все режимы тела**: `urlencoded` (список, объект или закодированная
      строка), `raw` с `options.raw.language`, `formdata` (только текстовые части — скрипт не может
      загрузить локальный файл) и `graphql`. Раньше понимался только `raw`, поэтому стандартный
      запрос токена client_credentials уходил с пустым телом. `error` неудачного вызова выводится в консоль скрипта
      как текст сообщения, а не как `{}`.
- [x] **Выключенный переключатель «Проверять SSL-сертификаты» действует на каждом переходе**: раньше он снова включался при
      редиректе на другой источник (origin), поэтому эндпоинт авторизации за балансировщиком нагрузки всё равно падал с
      «self signed certificate in certificate chain» после того, как пользователь выключил проверку. Теперь переключатель
      действует на каждом переходе; учётные данные по-прежнему удаляются при смене источника. Ошибка сертификата —
      в карточке ответа или из pre-request-скрипта — предлагает **«Отключить проверку SSL»** прямо на
      месте (`src/renderer/lib/tls-hint.ts`).
- [x] **Скрипты и плагины действительно работают в собранном приложении**: дочерние процессы песочницы — это
      исполняемый файл Electron в режиме `ELECTRON_RUN_AS_NODE`, где встроенного модуля `electron` не существует, —
      а им раньше передавался главный бандл приложения, чей `require('electron')` верхнего уровня
      там выбрасывает исключение. В режиме разработки он разрешается (npm-пакет лежит на диске), поэтому сбой был
      незаметен вплоть до установщика: каждый pre-request- и тестовый скрипт и каждый пользовательский плагин падал с
      «Script sandbox stopped». Теперь дочерние процессы запускают собственный бандл без electron
      (`src/main/sandbox-entry.ts` → `out/main/sandbox.js`).
- [x] **Тёплые песочницы скриптов**: запуск исполняемого файла Electron в роли Node и загрузка бандла стоят
      ~500 мс процессорного времени, а запуск коллекции платил эту цену дважды на запрос (pre-request + тест), — из-за чего
      одно ядро было загружено почти на 100 %, а к каждому запросу добавлялось полсекунды. Дочерний процесс, завершивший запуск
      без незавершённых операций, теперь остаётся «тёплым» (не более двух, удаляются после двух минут простоя) и
      передаётся следующему скрипту, который стартует за единицы миллисекунд. Изоляция не изменилась:
      совершенно новый контекст `vm` на каждый запуск внутри процесса, запущенного с
      `--disallow-code-generation-from-strings`, а дочерний процесс, чей запуск завершился по таймауту, упал или оставил
      незавершённый `pm.sendRequest`, уничтожается, а не используется повторно.
- [x] **pm.sendRequest работает на собственном движке приложения**, а не на голом `fetch`: скрипт, получающий
      токен, соблюдает ту же строгость TLS, набор CA, прокси, клиентские сертификаты и таймаут, что и
      запрос, отправленный из UI, а окно ожидания асинхронного завершения следует таймауту запроса, а не
      фиксированным 3 с. Cookie по-прежнему не применяются. Параметр `ca` передаёт корневые
      сертификаты Node по умолчанию вместе с набором пользователя — ведь его установка полностью заменяет хранилище доверия,
      из-за чего раньше ломался каждый публичный хост, как только пользователь добавлял доверенный корпоративный CA.
- [x] **Визуализатор** ответа: `pm.visualizer.set(template, data)` отрисовывается безопасным чистым
      шаблонизатором внутри наглухо закрытого `<iframe sandbox>` (без скриптов, без сети, строгая CSP);
      плюс автоматическая таблица без настройки для JSON-массивов.
- [x] Настройка **прокси** (undici `ProxyAgent`, авторизация на прокси + список исключений no-proxy) и **клиентских
      TLS-сертификатов** (для каждого хоста: PEM/PFX + необязательный CA + парольная фраза; байты читаются только в main).
      Настраивается в Настройки → Сеть.
- [x] **Рабочие пространства** (локальные, несколько): у каждого свои изолированные коллекции/окружения/глобальные переменные/
      история/вкладки/cookie в собственном каталоге; переключатель в заголовке окна (создать/переименовать/удалить/
      переключиться) с горячей перезагрузкой при переключении. Настройки уровня приложения, AI-провайдеры и секреты общие.
- [x] Режим запроса **GraphQL** (HTTP POST с редактором тела `{query, variables}`) **+ интроспекция
      схемы**: загрузка схемы endpoint'а, панель документации (типы → поля → тип) и
      автодополнение Monaco для корневых полей/типов по полученной схеме.
- [x] Клиент **Socket.IO** (`socket.io-client` на чистом JS в main; подключение, отправка событий, прослушивание,
      ограниченное переподключение) — realtime-режим с редактором события и данных **и сохранёнными шаблонами
      сообщений**.
- [x] Клиент **MQTT** (`mqtt.js` на чистом JS в main; подключение по mqtt(s)/ws(s), подписка, публикация) —
      realtime-режим с подпиской на топики и редактором публикации, **QoS на уровне соединения (0/1/2) и
      Last-Will & Testament**, плюс сохранённые шаблоны сообщений.
- [x] Клиент **gRPC** (`@grpc/grpc-js` + `@grpc/proto-loader` на чистом JS, без нативных модулей): вставьте или
      загрузите `.proto` **либо обнаружьте сервисы через Server Reflection**, выберите метод, отредактируйте сообщение
      запроса как JSON, задайте метаданные вызова, **клиентские сертификаты mTLS и дедлайн вызова** — и выполните его.
      Поддерживаются **unary, server-streaming, client-streaming и bidi**; открытый текст (h2c) или TLS; результаты
      поступают потоком в живой журнал (с полем Send/Finish для client-/bidi-потоков).
- [x] Резервная копия в **SQLite** (необязательная, `sql.js` на чистом WASM, без нативных модулей): экспорт текущего
      рабочего пространства (коллекции, окружения, глобальные переменные, история) в переносимый файл `.sqlite` и импорт
      обратно (Настройки → Данные). Файл — настоящая база SQLite с читаемыми столбцами плюс
      столбцами `json` без потерь. ПРИМЕЧАНИЕ: согласно CLAUDE.md, **хранилище JSON-документов остаётся каноническим
      бэкендом** — SQLite здесь лишь формат резервного копирования/обмена, а НЕ замена движка хранения
      (`better-sqlite3`, нативный модуль, по-прежнему сознательно не используется, чтобы сборка оставалась зелёной).
- [x] **Разделение на панели (как в Terminator)**: область редактора — бинарное дерево разбиений
      (`store/panes.ts`). Пресеты на 1/2/3/4/8 панелей, добавление панели справа/снизу, закрытие панели; у каждого
      разбиения свой перетаскиваемый разделитель, а у каждой панели — свой разделитель конструктора/ответа и своя раскладка.
      Вкладку может показывать только одна панель; полоса вкладок и активная панель синхронизированы (щелчок,
      фокус или ввод внутри панели делают её активной). Перетащите заголовок панели на другую панель, чтобы поменять их местами
      (центр) или разбить заново (края). Клавиатура: фокус / перемещение / изменение размера по направлению, развернуть,
      поменять большую панель местами с соседней группой — всё переназначается в Настройки → Горячие клавиши.
- [x] **Отсоединённые панели**: любую вкладку можно открыть в отдельном окне ОС (доступно по Alt+Tab, перемещается и меняет размер
      теми же сочетаниями клавиш). Окна обмениваются данными через main (рассылка `storage:changed`); ответ
      передаётся при отсоединении/возврате; события realtime/gRPC направляются окну-владельцу.
- [x] **Отмена / повтор в конструкторе запросов** (Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y): история для каждой вкладки,
      сгруппированная по областям (URL, Params, Headers, Body, Auth, Scripts, имя/описание). Внутри поля
      отменяется правка этой области, даже если фокус оттуда уже ушёл; когда ничего не в фокусе, отменяется последнее
      изменение вкладки — с переключением на соответствующую подвкладку и её подсветкой.
- [x] **Узкие панели прокручиваются, а не переносят содержимое**: строка запроса, ряды вкладок, подпанели и
      таблица ключ/значение сохраняют естественную ширину и прокручиваются вбок, так что ничто — и уж тем более кнопка Send —
      не обрезается и не оказывается вне досягаемости, когда панель сужают перетаскиванием.

- [x] **Перетаскивание вкладки или сохранённого запроса в сетку**: если бросить её на середину панели, она будет
      показана там; на край — эта панель разделится; на внешний край всей
      сетки — разделится сама раскладка (как в VS Code). Базовое приложение допускает до четырёх панелей;
      комплект «Дополнительные панели» поднимает предел до 16 и открывает пресет на 8 панелей.
- [x] **Комплекты возможностей** (`plugins/` рядом с приложением, см. docs/PLUGINS.md §10): базовое приложение — это HTTP
      + GraphQL, шесть схем авторизации, ru/en и четыре панели. WebSocket, SSE, Socket.IO, MQTT, gRPC,
      AI-ассистент, расширенные схемы авторизации, дополнительные языки и дополнительные панели живут каждый в своей
      папке и могут быть выключены (или убраны из списка) по отдельности. Их UI и их
      чанки рендерера отсутствуют, пока комплект не включён.
- [x] **Единый список плагинов** (Настройки → Плагины): комплекты и плагины с кодом находятся в одном списке, и каждая строка —
      это просто имя плюс **информация / удаление / включение**; описание, что добавляет плагин,
      разрешения и папка — за кнопкой информации. Единственная кнопка **«Выбрать плагин на компьютере…»**
      открывается в папке `plugins` — где ждут комплекты, которые никто не выбрал при установке, — и
      принимает папку или `.zip` из любого места на диске; главный процесс сам определяет, что это —
      комплект возможностей или плагин с кодом. Комплект, который ни разу не добавляли, вообще не показывается в списке, а
      удаление лишь убирает его из списка: его папка остаётся, так что его можно добавить снова.
- [x] **Язык интерфейса** (Настройки → Основные): русский и английский поставляются с приложением; немецкий и
      испанский — из комплекта «Дополнительные языки», а новый язык — это JSON-файл, положенный
      в этот комплект. Ключи перевода — *это и есть* русские строки, поэтому непереведённая строка
      деградирует до корректного русского текста, а не до сырого ключа. Полнота перевода проверяется эмпирически: приложение
      запускают на английском и прочёсывают его DOM в поисках кириллицы, включая вводный тур, названия комплектов, читаемые
      из `plugin.json`, и имена создаваемых по умолчанию рабочего пространства и запроса. Смена языка перезагружает
      окно, чтобы таблицы подписей на уровне модулей подхватили изменение.
- [x] **Проверка обновлений через GitHub**: сначала релизы, с откатом на теги версий для репозитория,
      который ещё не опубликовал ни одного релиза; результат различает «нет релизов», ограничение частоты запросов,
      таймаут и сбой сети, а также показывает дату и примечания к релизу.

- [x] **Установщик для Windows**: выбор языка (ru/en), который становится и языком интерфейса приложения, и
      языком вводного тура при первом запуске, — спрашивается один раз и наследуется экземпляром с повышенными правами,
      который запускается при установке «для всех пользователей»; страница выбора комплектов, включённых с самого начала; и при
      настоящем удалении — предложение удалить `%APPDATA%\Relay` — собственную папку Roaming пользователя, даже
      когда само удаление выполняется для всей машины (тихое удаление сохраняет данные).
- [x] **Сеть** (Настройки → Сеть): прокси выключен / **системный** (Chromium сам разрешает настройки ОС и
      PAC) / собственный с авторизацией и списком исключений; **общий набор CA** поверх системного хранилища
      доверия; переключатель проверки SSL; клиентские сертификаты для отдельных хостов (PEM или PFX); и

- [x] **Резервные копии** (Настройки → Данные): всё рабочее пространство — коллекции, окружения, глобальные переменные и
      история — экспортируется в **JSON** в базовом приложении, плюс **ZIP** (по файлу на каждый вид данных) и **SQLite**
      из комплекта «Дополнительные форматы резервных копий». Восстановление либо объединяет данные с текущим
      рабочим пространством, либо заменяет его (двухшаговое подтверждение). Секреты никогда не записываются в резервную копию.

- [x] **Отправка в терминал** (1.2): split-кнопка «cURL» рядом с «Код» выполняет разрешённый запрос —
      переменные, унаследованную авторизацию, включая Digest/NTLM и подписи AWS/OAuth 1/Hawk/Akamai, тело, cookie из jar,
      прокси, набор CA, переключатель SSL, редиректы, таймаут — через curl, HTTPie, wget (macOS/Linux)
      или PowerShell (Windows) в новом окне терминала (Windows Terminal/PowerShell, Terminal.app,

      ему команду оболочки), экранирует значения под целевой синтаксис (конфигурационный файл curl, POSIX
      shell, PowerShell), записывает скрипт в приватную временную папку, которую тот удаляет после выполнения, и
      выводит, чем выполнение в терминале отличается от обычного (скрипты не выполняются, неразрешённые переменные).

- [x] **Импорт переменных** (1.2) в глобальные переменные, окружение (существующее или новое) или коллекцию:

- [x] **Экспорт переменных** (1.2) глобальных переменных, окружения или переменных коллекции в виде экспорта окружения/глобальных
      переменных Postman, плоского JSON, `.env` или CSV — каждый формат читается обратно через импорт.
      Секретные значения записываются пустыми, если их явно не включить; копирование или сохранение с предпросмотром.
      Точки входа: заголовок раздела «Среды» боковой панели, контекстное меню окружения, просмотр переменных и
      каждый редактор переменных.
- [x] **Редактор переменных коллекции** (1.2): контекстное меню коллекции → «Переменные коллекции».
- [x] **Комплект тем** (1.2, комплект `theme-pack`, возможность `themes.extra`): 15 тем — Postman и

## 1.3 — Сеть, раскладка, проверка

### Сеть и сессия
- [x] **Нет автоматической проверки обновлений**: проверка при запуске и её настройка удалены; кнопка «Проверить сейчас»
      в разделе «О приложении» — единственный способ, которым выполняется проверка версии.
- [x] **Усиление защиты сессии**: без предварительного разрешения DNS, проверка орфографии выключена (она загружает словари), любой
      запрос разрешений (камера, геолокация, уведомления…) отклоняется, кроме доступа к буферу обмена. CSP
      (проверено, что она применяется к странице `file://`) не пропускает внешние изображения/скрипты/соединения,
      в том числе в HTML-предпросмотре ответа.
- [x] Перезагрузка или падение главного окна закрывает принадлежавшие ему realtime- и gRPC-соединения.

### Раскладка и внешний вид
- [x] **Режим для слабых ПК** (Настройки → Основные, заменяет «Экономить видеопамять»; значение из 1.2
      переносится): после перезапуска — без GPU, программная композиция, режим слабого устройства Chromium, без
      анимаций/теней/размытия и простой редактор на textarea вместо Monaco (Monaco вообще не загружается)
      с тем же автодополнением `{{`. Все возможности продолжают работать.
- [x] **Прикрепляемая боковая панель**: слева / справа / снизу — перетаскиванием заголовка к краю (края подсвечиваются;
      отпущенная в другом месте, панель остаётся на месте), плавающая — кнопкой в заголовке. Снизу раскладывается в три
      колонки. Размер и положение сохраняются.
- [x] **Перемещаемые запрос и ответ** внутри каждой панели: ответ — за строку состояния, запрос — за ручку слева от
      названия; сверху / снизу / слева / справа, вторая часть занимает противоположную сторону. Плавающий ответ —
      кнопкой. Раскладки из 1.2 переносятся.
- [x] **Обмен вместо сдвига**: навигация, перенесённая на край, где стоит ответ (или наоборот), меняется с ним местами.
- [x] **Ровные стыки**: заголовок запроса, шапка навигации и строка статуса ответа одной высоты, вертикальный
      разделитель между запросом и ответом виден.
- [x] **Импорт перетаскиванием файлов**: коллекции (Postman, Insomnia, OpenAPI/Swagger, HAR, cURL), окружения и
      глобальные переменные Postman, переменные `.env`/CSV и темы Relay распознаются по каждому файлу; брошенный файл
      больше не может увести окно на свою страницу.
- [x] **Палитра команд**: действия перечисляются перед запросами.
- [x] **Пользовательские темы**: Настройки → Внешний вид → Мои темы → Загрузить тему… читает один JSON-файл (тему,
      список тем или `themes.json` комплекта), с тем же белым списком цветов, что и у комплектов; хранятся на уровне приложения.
      Руководство по созданию: `docs/THEMES.md` (EN) / `docs/THEMES.ru.md` (RU).

### Протоколы (проверено на локальных серверах, 61 тест)
- [x] SSE работает на хостах с undici 7 (встроенный диспетчер) и сообщает, почему происходит повторная попытка;
      многобайтовые символы UTF-8, разбитые между чанками, декодируются правильно.
- [x] WebSocket: показывается настоящая причина сбоя рукопожатия; таймаут рукопожатия 30 с; подпротоколы можно

- [x] MQTT: корректный DISCONNECT (без Last Will при обычном отключении); логин, пароль, client id и

- [x] Socket.IO: останавливается, исчерпав лимит повторных попыток, с финальным событием; фильтр событий в UI.
- [x] gRPC reflection загружает транзитивные зависимости; некорректные метаданные дают событие ошибки, а не отклонённый вызов.
- [x] Интроспекция GraphQL следует редиректам.

### Авторизация (проверено на векторах из спецификаций, 51+ тестов)
- [x] AWS SigV4: `x-amz-content-sha256` для S3, однократное кодирование URI для S3.
- [x] Akamai EdgeGrid хеширует только тела POST; Digest учитывает `stale=true` и поддерживает SHA-512-256;
      флаги NTLM Type 3 маскируются; OAuth 1.0 подписывает повторяющиеся ключи формы (в движке и при отправке в терминал).
- [x] Подписи, привязанные к запросу, пересчитываются на каждом переходе редиректа и никогда не выпускаются для другого хоста.
- [x] Криптографически стойкие nonce для Hawk и OAuth 1.0.
- [x] **Вход OAuth 2.0 через браузер**: URL авторизации с `state` и PKCE `code_challenge` (S256),
      loopback-редирект перехватывается на `http://127.0.0.1:<port>` (RFC 8252), код обменивается на токен автоматически;
      поле кода также принимает вставленный URL редиректа.
- [x] Токен, обновлённый при 401, сохраняется в запросе (или в папке/коллекции, от которой тот наследует авторизацию).
- [x] Авторизация, которую невозможно построить (некорректный JSON для JWT, некорректный PEM…), останавливает отправку с ошибкой `auth`,
      а не отправляет запрос без авторизации.
- [x] Импорт/экспорт Postman нативно сопоставляет AWS, Hawk, NTLM, OAuth 1.0, EdgeGrid, JWT и ASAP;
      неизвестная схема импортируется как «без авторизации», но никогда как «наследовать».
