## Relay 1.3.3

**Русский**

- **Проверки в тестах больше не «проходят» сами по себе.** Раньше неизвестное слово в проверке — опечатка вроде `.to.be.tru`, `.to.exist`, `pm.response.to.be.ok` или `pm.response.to.be.json` без скобок — ничего не проверяло, и тест засчитывался как пройденный при любом ответе. Теперь такое слово проваливает тест с сообщением «Invalid or unsupported assertion property», а `exist`, `NaN`, `ok` у ответа и `json` действительно проверяют значение.
- **Работают цепочки `.at.least` / `.at.most`.** Из-за них падал, например, сниппет «Status is 2xx». Добавлены `within`, `instanceOf` (в том числе для JSON из ответа), `satisfy`, `ownProperty`, `.all.keys` / `.any.keys` / `.include.keys`, `.same.members` / `.ordered.members`, `.lengthOf.above(…)`, связки `but`, `also`, `still`, `does` и `pm.expect.fail()`.
- **Проверки ответа:** `pm.response.to.have.status(…)`, `.header(name, value)`, `.body(…)`, `.jsonBody(path, value)`, `pm.response.to.be.ok`, `.success`, `.clientError`, `.serverError`, `.notFound`, `.unauthorized` и другие классы статусов, `.json`, `.html`, `.xml`, `.withBody`, в том числе с `.not`. То же работает для ответа `pm.sendRequest`.
- Сравнения (`above`, `below`, `within`…) требуют число или дату, а `.empty` — строку, массив или объект: неверный тип проваливает проверку и под `.not`. Сообщения об ошибке стали точнее, например «expected response 404 to have status 200 (got 404 Not Found)».
- Каждый сниппет из комплекта «Сниппеты для скриптов» проверяется тестом на то, что использует только поддерживаемые проверки.

**English**

- **Test assertions no longer pass by themselves.** An unknown word in an assertion — a typo such as `.to.be.tru`, `.to.exist`, `pm.response.to.be.ok` or `pm.response.to.be.json` without parentheses — used to check nothing, so the test passed whatever the response was. Such a word now fails the test with «Invalid or unsupported assertion property», and `exist`, `NaN`, a response's `ok` and `json` really check the value.
- **`.at.least` / `.at.most` chains work.** They broke, for example, the «Status is 2xx» snippet. Added `within`, `instanceOf` (also for JSON from the response), `satisfy`, `ownProperty`, `.all.keys` / `.any.keys` / `.include.keys`, `.same.members` / `.ordered.members`, `.lengthOf.above(…)`, the `but`, `also`, `still`, `does` chains and `pm.expect.fail()`.
- **Response assertions:** `pm.response.to.have.status(…)`, `.header(name, value)`, `.body(…)`, `.jsonBody(path, value)`, `pm.response.to.be.ok`, `.success`, `.clientError`, `.serverError`, `.notFound`, `.unauthorized` and the other status classes, `.json`, `.html`, `.xml`, `.withBody`, also with `.not`. The same works on a `pm.sendRequest` response.
- Comparisons (`above`, `below`, `within`…) need a number or a date and `.empty` a string, array or object: a wrong type fails the assertion even under `.not`. Failure messages are more precise, e.g. «expected response 404 to have status 200 (got 404 Not Found)».
- Every snippet of the «Script snippets» pack is checked by a test to use only supported assertions.
