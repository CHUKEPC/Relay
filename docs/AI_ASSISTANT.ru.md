# AI_ASSISTANT.md — встроенный мультипровайдерный AI-ассистент

*[English version](AI_ASSISTANT.md)*

Он поставляется как комплект возможностей `ai-assistant`. Пользователь подключает **свой собственный** API-ключ для любого
поддерживаемого провайдера и получает ассистента **внутри** приложения, который понимает текущий запрос,
ответ и окружение и может помогать проектировать и отлаживать API.

Все AI-вызовы выполняются в **главном процессе** (Node). Поскольку мы не в браузере, **проблем с CORS
нет** и не нужны никакие заголовки, переопределяющие «доступ из браузера».

## Поддерживаемые провайдеры

Единый нормализованный интерфейс чата с адаптерами для каждого провайдера. Пользователь может зарегистрировать несколько
профилей провайдеров и переключать активного провайдера/модель из AI-панели.

### 1) OpenAI (ChatGPT)
- Endpoint: `POST https://api.openai.com/v1/chat/completions`
- Заголовки: `Authorization: Bearer <API_KEY>`, `Content-Type: application/json`
- Тело: `{ "model": "...", "messages": [...], "stream": true, "temperature": ... }`
- Потоковая передача: SSE; каждая строка `data:` — это JSON с `choices[0].delta.content`. Поток завершается строкой
  `data: [DONE]`.
- Модели: `GET https://api.openai.com/v1/models`.

### 2) Anthropic (Claude)
- Endpoint: `POST https://api.anthropic.com/v1/messages`
- Заголовки: `x-api-key: <API_KEY>`, `anthropic-version: 2023-06-01`, `Content-Type: application/json`
- Тело: `{ "model": "...", "max_tokens": N, "system": "...", "messages": [{role, content}], "stream": true }`
  - Примечание: Anthropic принимает системный промпт в поле верхнего уровня `system` (а не как сообщение), роли —
    только `user`/`assistant`, а `max_tokens` **обязателен**.
- Потоковая передача: SSE с типизированными событиями; текст накапливается из событий `content_block_delta`, у которых
  `delta.type === "text_delta"` (`delta.text`). Обрабатываются `message_start`, `content_block_start`,
  `content_block_stop`, `message_delta`, `message_stop`.
- Модели, предлагаемые по умолчанию: последнее семейство Claude (например, Opus/Sonnet/Haiku). Список моделей должен
  оставаться редактируемым для пользователя, поскольку названия со временем меняются.

### 3) OpenRouter
- Endpoint: `POST https://openrouter.ai/api/v1/chat/completions` (схема, совместимая с OpenAI)
- Заголовки: `Authorization: Bearer <API_KEY>`, необязательные `HTTP-Referer` и `X-Title` для указания
  приложения.
- Модели: `GET https://openrouter.ai/api/v1/models` — список для выбора модели заполняется динамически.

### 4) Собственный OpenAI-совместимый (локальные и прочие)
- Настраиваемый **базовый URL** (например, `http://localhost:11434/v1` для Ollama,
  `http://localhost:1234/v1` для LM Studio, Groq, Together и т. д.).
- Та же структура запросов и потоковой передачи, что у OpenAI. Для локальных серверов API-ключ необязателен/может быть пустым.

## Нормализованный интерфейс

```ts
type Role = 'system' | 'user' | 'assistant' | 'tool'
interface ChatMessage { role: Role; content: string; toolCalls?: ToolCall[]; toolCallId?: string }

interface ProviderConfig {
  id: string
  kind: 'openai' | 'anthropic' | 'openrouter' | 'openai-compatible'
  label: string
  baseUrl?: string          // for openai-compatible / overrides
  apiKeyRef?: string        // ref into safeStorage; NEVER the raw key
  defaultModel: string
  extraHeaders?: Record<string, string>
}

// main process:
async function* streamChat(provider, model, messages, opts): AsyncIterable<Delta>
//   Delta = { type: 'text', text } | { type: 'tool_call', call } | { type: 'done' } | { type: 'error', error }
```

Слой адаптеров преобразует эту нормализованную форму в формат каждого провайдера и обратно, поэтому UI
и остальное приложение никогда не ветвятся в зависимости от провайдера.

## Внедрение контекста (что делает ассистента полезным)

Перед отправкой сообщения пользователя ассистент получает компактный структурированный **блок контекста**
(как системное сообщение или как начальный пользовательский контекст), описывающий состояние приложения:

- Активный запрос: метод, URL (переменные показаны и в сыром виде, и разрешёнными, но с замаскированными секретами),
  заголовки, тип тела + усечённое тело, тип авторизации.
- Последний ответ (если есть): статус, время, размер, усечённое тело (отформатированное, ограниченное бюджетом
  токенов, например первые ~4–8 КБ), ключевые заголовки ответа.
- Имя активного окружения и имена **несекретных** переменных (секретные значения маскируются).
- При необходимости — окружающая структура коллекции (только имена) для задач вроде «куда сохранить».

Правила:
- **Никогда** не помещать в промпт сырые значения секретов (API-ключи, пароли, токены). Маскировать их.
- Ограничивать большие тела; сообщать модели, что они усечены.
- Соблюдать бюджет токенов; первым отбрасывать самый старый контекст.

## Основные сценарии (P0)

- **Объяснить этот ответ** — кратко описать статус/структуру/вероятный смысл; найти ошибки.
- **Сгенерировать запрос** по описанию на естественном языке (метод, URL, заголовки, тело).
- **Исправить эту ошибку** — по ответу 4xx/5xx или сетевой ошибке предложить конкретные изменения.
- **Написать тест** — сгенерировать фрагмент `pm.test(...)` для текущего ответа.
- **Преобразовать** — в cURL или на другой язык.
- Свободный чат об API с доступом к контексту приложения.

Каждое сообщение ассистента, содержащее применимый результат (запрос, набор заголовков, скрипт),
получает элемент **«Применить»**, который записывает его в текущий запрос/вкладку.

## Вызов инструментов (P1 — ассистент может *действовать*)

Определите небольшой набор инструментов, которые может вызывать модель (`tools` у OpenAI/OpenRouter, `tools` у Anthropic). Выполняйте
их в main, возвращайте результаты и повторяйте цикл, пока модель не выдаст окончательный ответ.

Предлагаемые инструменты:
- `get_current_request()` / `get_last_response()` — чтение состояния приложения.
- `update_current_request({ method?, url?, headers?, body?, auth? })` — изменение открытого запроса.
- `create_request({ collectionId?, name, ...spec })` — добавление запроса в коллекцию.
- `set_variable({ scope, key, value })` — установка переменной окружения/глобальной переменной.
- `send_request({ requestId? })` — фактическая отправка запроса.

**Безопасность**: изменяющие инструменты и инструменты отправки требуют **явного подтверждения пользователя** в UI перед
выполнением (diff/предпросмотр + «Одобрить»/«Отклонить»), если только пользователь не включил переключатель «автоприменения».
Никогда не позволяйте ассистенту выносить секреты наружу; для секретных полей инструменты возвращают замаскированные значения.

## Безопасность и приватность

- API-ключи хранятся через Electron `safeStorage`; расшифровывает их только главный процесс.
- Рендерер ссылается на провайдеров по `id`/`apiKeyRef`, никогда — по сырому ключу.
- Никакой телеметрии. Единственный исходящий трафик — это (а) собственные API-запросы пользователя и (б) его
  собственные обращения к AI-провайдеру.
- В настройках должно быть очевидно, какому провайдеру/endpoint'у отправляется ключ (особенно в случае
  собственного базового URL).
